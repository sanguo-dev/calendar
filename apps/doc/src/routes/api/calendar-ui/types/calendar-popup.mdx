# CalendarPopupOptions

日期格 popup 的**交互**配置，全部可选：不写就按默认（click + dialog + auto 定位）生效。

内容不在这里：每一天的内容写在 [DayContent](/api/calendar-ui/types/calendar-adapter) 的 `popup` 字段里，由 `contentDay` 或 adapter 提供。

## 引入

```ts
import type {
  CalendarPopupOptions,
  DayPopupContent,
  DayPopupItem,
  DayPopupPlacement,
  DayPopupStringItem,
  DayPopupTrigger,
} from "@sanguo-dev/calendar-ui";
```

## 定义

```ts
interface CalendarPopupOptions {
  trigger?: DayPopupTrigger;
  placement?: DayPopupPlacement;
  role?: "dialog" | "tooltip";
  ariaLabel?: string;
}

interface DayPopupContent {
  title?: string;
  items: readonly DayPopupItem[] | (() => readonly DayPopupItem[]);
}

type DayPopupStringItem = readonly [time?: string, title?: string, detail?: string];
type DayPopupItem = DayPopupStringItem | Node;
type DayPopupTrigger = "click" | "hover" | "focus" | "auto";
type DayPopupPlacement = "auto" | "top" | "bottom" | "center";
```

## 字段

| 字段        | 类型                    | 默认                          | 说明                           |
| ----------- | ----------------------- | ----------------------------- | ------------------------------ |
| `trigger`   | `DayPopupTrigger`       | `"click"`                     | 触发方式；移动端没有 hover     |
| `placement` | `DayPopupPlacement`     | `"auto"`                      | 定位方式；`center` 由 CSS 居中 |
| `role`      | `"dialog" \| "tooltip"` | click 为 dialog，其余 tooltip | popup 的 ARIA role             |
| `ariaLabel` | `string`                | -                             | popup 根节点的 `aria-label`    |

## 内容类型

「有没有 popup」由内容决定，而不是由这个选项决定：

```ts
contentDay: (day) => (hasEvent(day) ? { popup: { items: [...] } } : null);
```

- 内容里有 `popup` → 这一天有 popup，日期格右上角有绿点；
- 没有 `popup` 字段，或内容返回 `null` → 没有 popup，也没有绿点；
- `items` 是数组或返回数组的函数。传函数时，渲染期只判断有没有，内容推迟到打开弹层时才算一次；
- `title` 可以直接覆盖头部「日期 · 条数」文案。

## 项类型

`DayPopupStringItem` 是 `[time, title, detail]` 三元组，字段都可以省略；三个字段都为空时这一项直接丢掉：

- `time` / `title` 生成 `.cui__popup-title`（内含 `.cui__popup-time` / `.cui__popup-name`）；
- `detail` 生成 `.cui__popup-detail`；
- 字段省略或传空字符串时不渲染对应元素。

`DayPopupItem` 也可以是 `Node`：库只包一层 `.cui__popup-item`，内部结构、类名和样式完全由使用方决定。Node 要在 `items` 里新建，不要跨日期复用同一个实例。

`items` 长度就是弹层头部「日期 · 条数」里的条数。

## 用法

```ts
createCalendarUI(container, {
  popup: {
    trigger: "click",
    ariaLabel: "日期详情",
    placement: "auto",
  },
  contentDay: (day) => {
    const entries = POPUPS[`${day.year}-${day.month}-${day.day}`];
    return entries
      ? {
          popup: {
            items: entries.map((entry) => [entry.time, entry.title, entry.detail] as const),
          },
        }
      : null;
  },
});
```

需要延迟构造内容时，把 `items` 换成函数：

```ts
contentDay: (day) => {
  const entries = POPUPS[`${day.year}-${day.month}-${day.day}`];
  return entries ? { popup: { items: () => entries.map(buildRow) } } : null;
},
```

## 说明

- 内容在每次重绘时对每个可见格子调用一次（单月 42 次），用来判断有没有绿点；内容随内容留在格子上，打开时直接用；
- `items` 传函数时，内容推迟到打开那一次才求值；
- `contentDay` / `items` 必须是同步函数：数据要在创建日历前准备好，不能返回 Promise，也不要在里面发请求；
- 内容里有 `popup` 时格子右上角显示绿点，颜色是 `--cui-popup-dot`；
- 弹层追加到 `body`，不打断日历布局；点击其他日期、点击空白处、按 `Esc`、换月、滚动或缩放页面都会关闭，没有关闭按钮；
- `trigger: "auto"` 在支持 hover 的设备上等同 `hover`，触摸设备上等同 `click`；`hover` 关闭前有约 120ms 的缓冲，方便鼠标移进弹层；
- `placement: "auto"` 优先放在格子下方，空间不足时翻到上方，并夹在视口内；`center` 由 CSS 居中。

## 错误

| 异常        | 场景                                                                                               |
| ----------- | -------------------------------------------------------------------------------------------------- |
| `TypeError` | `popup` 不是对象、`trigger` / `placement` / `role` 取值非法、`ariaLabel` 不是字符串                |
| `TypeError` | `contentDay(day)` 返回的不是对象 / `null`，或 `items` 既不是数组也不是返回数组的函数，或项类型非法 |

完整示例和样式写法见 [日期格 popup](/calendar-ui/popup)。
